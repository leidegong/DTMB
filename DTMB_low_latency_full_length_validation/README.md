# 低时延链路全长验证（1099帧，2026-09-08）

入口：`validate_low_latency_full_length.m`。此前 `DTMB_low_latency_final_output/` 里的最终结果只跑了16帧样本（`fast_16frame_sync_input.mat`），本次把同一套运行配置跑满 `DTMB_1100Frame_Sync_Equalized_Packet.mat` 的1099帧。

`QUICKSTART_LOW_LATENCY_FINAL.m` 仍是16帧冒烟测试，两个入口输出到不同目录，互不覆盖。

## 结论

**质量与时延结构：全长通过。计算吞吐：本测试台判不了，需要流式基准。**

## 质量与结构（全长成立）

| 项 | 结果 |
|---|---|
| 依赖审计 | 24个依赖文件，无FEC/学习型逆信道/时间交织依赖 |
| 时间交织缓存 | 0 帧 |
| 最小输入缓存 | 1 帧 |
| 最小信号时延 | 0.6255 ms |
| 判决EVM | 中位数 0.13522，p95 0.14326 |
| CPE锁定后重捕获 | 0 次 |
| 对完整FEC重构（79个FEC有效帧） | NMSE **-16.258 dB**，相关 **0.988093** |
| 对完整FEC重构（全部1099帧） | 相关 **0.987809** |

与 `benchmark_low_latency_passive_radar` 的 -16.26 dB / 0.9881 一致。16帧样本的EVM中位数为0.1337，全长为0.13522，无系统性偏移。

逐帧计算时间在整个采集上没有漂移（见 `low_latency_full_length_timing.png` 左图），说明不存在随运行时长累积的退化。

## 计算吞吐：判据落在两把尺子之间

单帧预算为0.625 ms（7.56 MHz符号率、4725符号/帧）。

| 口径 | 值 | 含义 |
|---|---:|---|
| 稳态核心中位数 | 0.4748 ms | 内层计时器 |
| 稳态核心p95 | 0.7832 ms | 内层计时器 |
| 稳态核心最大值 | 6.3722 ms | 单次离群 |
| 内层核心+信道中位数 | 0.5569 ms | **下界，实时因子0.891** |
| 整链墙钟 | 1.0288 ms/帧 | **上界，实时因子1.646** |
| 3次重复的墙钟 | 0.8905--1.0288 ms/帧 | 实时因子1.425--1.646 |

判定结果为 `inconclusive_harness_bounded`。两把尺子量的不是同一件事：

- **内层计时器**只计算法本身，不含批处理脚手架（1099帧输出数组的预分配、每帧写入大数组、成形波形的整段保留）。流式部署不付这些开销，所以是**下界**。
- **整链墙钟** `pipeline_wall_s/num_frames` 把信道前端和核心放在同一把尺子上、每项开销只计一次，但它把批处理脚手架也算进去了，所以是**上界**。

真实的流式吞吐在0.891--1.646之间，本批处理测试台无法进一步收窄。

另外，1094个稳态帧中有180帧（16.5%）单帧超出0.625 ms预算。**单帧超预算不等于跟不上**——带缓冲的流式实现只要平均代价在预算内就不会累积落后；决定性的量是均值而不是中位数。但本测试台给不出可信的均值，见上。

## 相对16帧样本的修正

16帧摘要报的稳态核心中位数为0.5537 ms，据此写下的"实时吞吐以 `steady_compute_ms_per_frame_*` 为准"不成立：

- 该字段是内层计时器的中位数，既不含信道前端也不含任何开销，只能作下界使用
- 16帧样本看不到尾部。全长跑出的p95为0.7832 ms、最大值6.3722 ms、16.5%的帧超预算，这些在16帧里都不可见
- 单次运行的计时在本机摆动超过10%，所以任何单次数字都不能当结论。本入口默认重复3次并报区间

## 未决

要给出实时结论，需要一个真正的流式基准：逐帧喂入、不预分配整段输出、不保留整段成形波形，测量稳态的每帧平均代价。这属于实现工程，不影响本报告中算法侧的任何结论。
